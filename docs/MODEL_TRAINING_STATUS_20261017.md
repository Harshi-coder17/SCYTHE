# SCYTHE model training status — 2026-10-17

## What has now been trained

The project has trained several experimental models: MobileCLIP-S0 v1/v2 visual classifiers, LightGBM URL candidates through `lightgbm_fresh_v3`, a multi-source URL candidate, an earlier paired fusion v1, and a new paired fusion development candidate built from the latest prospectively captured cohort. None of these artifacts is approved for production scoring. Runtime fusion remains fail-closed and experimental candidates remain shadow-only.

The latest fresh URL dataset is `lightgbm_dataset/fresh/dataset_v3/` (145,767 distinct URLs). It combines UCI, fresh OpenPhish, and Tranco proxy controls. Its strong internal metrics are source-confounded; the model trained on it did not transfer acceptably to the already-inspected PhishVN benchmark. The multi-source candidate improved ranking substantially over the earlier URL-only model on that same development benchmark, but its frozen-threshold false-positive rate remained 562 per 10,000 benign rows and recall was 50.4%. That benchmark is no longer an untouched release test.

The newly built paired dataset is `lightgbm_dataset/prospective_v2_dev_v2/`. It contains 17 eligible screenshots after removing a domain already present in an evaluated holdout: 10 training rows and 7 validation rows, split by registrable domain. All labels are feed-supported phishing or Tranco-proxy benign; there are **zero independently supported release labels**, **zero verified campaign groups**, and no scan-signal evidence. The pipeline extracted MobileCLIP v2 three-crop embeddings, retained contemporaneous available provider evidence, preserved unavailable fields as null, validated checksums and exclusions, and trained `scythe_fusion_v2_dev1` with five-fold grouped out-of-fold component predictions.

The new fusion candidate's validation result is deliberately recorded even though it is poor: PR-AUC **0.286**, ROC-AUC **0.500**, precision **0.286**, recall **1.000**, and **5 false positives among 5 proxy-benign validation rows**. Every predicted probability was 0.5 because the registered LightGBM configuration cannot learn useful splits from ten training samples. This is evidence that the capture cohort is far too small for fusion training, not a candidate for promotion. The result must not be used to set operational thresholds.

A further URL-only development run added 94 eligible PhishStats source-reported positives after registered holdout/domain exclusions and conflict quarantine. The API snapshot stopped on HTTP 429 after nine successful pages (900 records); the request was not retried. PhishStats' raw pages stay outside the application repository and are not redistributable. The added data did not solve transfer: the new URL model's validation PR-AUC is **0.969** with 44.6 false positives per 10,000 proxy-benign validation rows, but on the previously inspected paired PhishVN development slice it achieved PR-AUC **0.726**, ROC-AUC **0.912**, recall **0.425**, and **476 false positives per 10,000 benign rows** at its frozen validation threshold. The v1 model on the same slice had PR-AUC 0.724, ROC-AUC 0.914, recall 0.504, and 562 false positives per 10,000. This small tradeoff is not a release improvement, and the PhishVN comparison cannot be treated as fresh external evidence.

The MobileCLIP v3 development candidate has now also been trained. It adds 81 quality-screened images (71 phishing, 10 benign) from Seirin and Phishpedia to the unchanged v2 train/validation base; seven other candidate images were excluded for domain conflict, exact duplication, or visual near-duplication. It used frozen MobileCLIP-S0 three-crop embeddings, and did not open or score test images. On the same 2,011-image validation set, v3 PR-AUC/ROC-AUC were **0.9436/0.9619**, versus v2's **0.9439/0.9620**. At each model's own frozen validation threshold, v3 had 154 false positives and recall 0.929, versus v2's 170 false positives and recall 0.939. The benign false-positive rate remains **1,332 per 10,000** and is especially high on the desant login-page source (4,421 per 10,000). This modest validation tradeoff does not establish generalization; the added examples are highly phishing-heavy, selected for readable lure/login content, publisher-labeled, and have no independent adjudication or verified campaign grouping.

## Frozen artifacts and boundaries

- `mobileclip-dataset/artifacts/mobileclip_v1/` and `mobileclip_v2/` remain unchanged. v2 has already shown a high false-positive rate on its available development data and is not deployment-ready.
- `lightgbm_dataset/prospective_v1/artifacts/scythe_fusion_v1/` remains unchanged.
- The new fusion bundle is under `lightgbm_dataset/prospective_v2_dev_v2/artifacts/scythe_fusion_v2_dev1/`; it is experimental only, has no release holdout, and does not replace any runtime model.
- The new URL-only candidate is `lightgbm_dataset/fresh/artifacts/lightgbm_multisource_url_dev_v2/`, trained from the matching v2 development data. Its model bundle and PhishVN comparison are checksum-addressed; the local PhishStats raw pages are under `lightgbm_dataset/source/phishstats_private/` and must not be redistributed.
- The new visual candidate is `mobileclip-dataset/artifacts/mobileclip_v3_dev_v1/`; the original MobileCLIP v1/v2 artifacts and split membership remain frozen. V3 is not an external holdout result and does not replace the currently configured model.
- Phish360, PhishVN, and previously scored external domains remain development benchmarks or exclusions. They cannot certify the new models.
- Synthetic records remain test fixtures only. No synthetic feature values were used in these candidates.

## What still blocks model deployment

1. A larger paired cohort with independently supported per-sample labels, non-proxy benign examples, verified domain/campaign grouping, contemporaneous screenshots and SCYTHE observations, and real scan-signal evidence.
2. A new untouched, temporally later holdout registered before model selection. Previously inspected PhishVN, Phish360, and starter-set outcomes remain development evidence.
3. Acceptable recall and false-positive rates on that holdout under a documented operational policy; the current URL and image candidates fail this bar.
4. Sufficient and consistent coverage for the v10 feature contract. The current paired cohort has zero scan-signal coverage and sparse SCYTHE predictors.
5. A fresh shadow evaluation and explicit release review before any runtime model promotion. Do not disable `is_placeholder`, suppress the fail-closed behavior, or enable automatic incident creation based on these experimental outputs.

## Reproducibility

The paired data builder is `lightgbm_dataset/build_paired_cohort_v2.py`. It refuses to overwrite a completed output, binds screenshots and embeddings by SHA-256, applies registered evaluation exclusions, and writes an immutable dataset checksum list. Training used `lightgbm_dataset/prospective_fusion.py` with the local MobileCLIP research environment. The model bundle includes its own checksums, validation predictions, threshold, feature contract, environment locks, and training manifest.

## Data-source research notes

The [OpenPhish academic-use program](https://www.openphish.com/academic_use.html) offers a real-time feed and 30-day archive subject to eligibility, approval, non-commercial use, attribution, and non-sharing terms. PhishTank recommends registered application keys for frequent downloads; unauthenticated downloads are limited, which explains why repeated feed retries are not a sound way to increase volume ([developer information](https://phishtank.org/developer_info.php)). [PhishStats](https://phishstats.info/api-docs) allows lawful security research under tier quotas but prohibits redistribution of raw feeds; the snapshot was stopped at HTTP 429 and only 94 novel records remained after exclusions. The recently published [Zenodo multimodal dataset](https://zenodo.org/records/21379702) advertises 60,000 URL records and 21,311 screenshots, but the record's public metadata does not display a license. It is therefore not added to this project's training corpus until reuse terms are established. The [Phishpedia benchmark](https://github.com/lindsey98/Phishpedia) is a useful research reference, but dataset redistribution and underlying content rights should be checked before importing additional images.

## 2026-10-17 training update: URL-Phish v4 and paired-cohort v3

This addendum records additional work completed after the initial status above. Existing v1/v2/v3 model bundles and frozen evaluations were left unchanged; runtime scoring, risk fusion, placeholder flags, alerts, and incident behavior were not modified.

### URL candidate

A new publisher dataset was downloaded from [URL-Phish v2 on Mendeley Data](https://data.mendeley.com/datasets/65z9twcx3r/2) (DOI 10.17632/65z9twcx3r.2). The archive file checksum is recorded in the v4 manifest. The dataset page reports CC BY 4.0, but its underlying PhishTank and third-party URL content may carry additional terms; do not redistribute the raw snapshot without reviewing those rights.

The normalized, domain-grouped v4 dataset contains **229,598 unique URLs**, including **84,095 eligible URL-Phish rows** after registered holdout exclusions, development-set overlap removal, invalid-URL rejection, conflicting-domain quarantine, and canonical duplicate removal. It has 183,325 training rows and 46,273 validation rows. Source labels are metadata only; URL predictors are recomputed with the SCYTHE feature helper, the publisher's numeric features are ignored, and missing SCYTHE enrichment remains null/unavailable. The corpus adds substantial scale, but its publisher-reported phishing labels and proxy-benign rows remain imperfect supervision. There is no capture-time guarantee.

Version 3 was frozen with a discovered defect: 820 duplicate normalized URLs. Version 4 removes them and is the corrected candidate. Its validator passed checksum, split, exclusion, source provenance, null-preservation, feature-order, model-reload parity, and PhishVN isolation checks. The v4 model's validation PR-AUC is **0.782**, ROC-AUC **0.935**, recall **0.723**, and false-positive rate **766 per 10,000 proxy/publisher-benign rows** at its validation-selected threshold. Calibration is weak (Brier **0.101**, 10-bin ECE **0.137**).

On the same previously inspected 1,995-row PhishVN development slice, v4 scored PR-AUC **0.811**, precision **0.817**, recall **0.481**, and **344 false positives per 10,000 benign rows** at its frozen validation threshold. This improves on v2's 476/10,000 FPs and 0.425 recall, but it remains a contaminated development benchmark: prior results from this corpus informed development. It is not evidence for release or deployment.

Artifacts are under `lightgbm_dataset/fresh/dataset_dev_v4/`, `lightgbm_dataset/fresh/artifacts/lightgbm_multisource_url_dev_v4/`, and `lightgbm_dataset/fresh/external_evaluations/phishvn_v4_multisource_v4_comparison_dev_v1/`. The v4 validator is `lightgbm_dataset/validate_url_candidate_dev_v4.py`.

### New prospective paired cohort and fusion experiment

A bounded fresh-feed capture effort generated a small prospective cohort. After capture-quality review and registered exclusions, the paired development dataset has **16 images**: 10 training rows (5 feed-positive and 5 Tranco-proxy negative) and 6 validation rows (2 feed-positive and 4 proxy-negative). There are no independently adjudicated labels, verified campaign identifiers, or real scan-signal coverage. Provider lookups are sparse and are not sufficient to train the full v10 fusion contract.

Fusion v3 was trained as an isolated experiment. Every validation probability was 0.5; PR-AUC was **0.333**, ROC-AUC **0.5**, and all four proxy-benign validation samples were false positives (10,000 per 10,000). This cohort cannot train a useful fusion model. Keep all outputs diagnostic only and retain the runtime fail-closed state.

- MobileCLIP baseline, crop sensitivity, validation audit, and ingestion tests: **18 passed**.

## 2026-10-17 update: PhreshPhish cohort and newly dated URL evaluation

The PhreshPhish training split was added as a separate experimental corpus, pinned to repository revision `eabec4b7a66324b79cc8a0ad856d1731dc26fe1a` under CC BY 4.0. Only URL, label, target, date, page SHA-256, and language metadata were downloaded; raw HTML was not. After filtering previously evaluated and registered domains, invalid URLs, duplicate canonical URLs, and conflicting-label domains, **160,999 unique URLs** remain: 128,451 training and 32,548 validation. The split is deterministic and grouped by registrable domain and exact captured-page hash. Cross-domain campaign IDs are not supplied, so campaign separation is not established. The source's paper describes feed/telemetry-derived labels and representative human quality review; the labels are not individually independently adjudicated. The upstream test split was registered before opening labels or HTML; it has since been scored once against the frozen candidate, as detailed below.

Attribution and use restriction: Dalton et al., “PhreshPhish: A Real-World, High-Quality, Large-Scale Phishing Website Dataset and Benchmark,” arXiv:2507.10854 (2025, revised 2026), dataset release CC BY 4.0; the dataset card says it is for anti-phishing research. Retain this attribution and do not redistribute the raw URL metadata outside the license and underlying-source terms.

An isolated URL-only LightGBM candidate was trained at `lightgbm_dataset/fresh/artifacts/lightgbm_phreshphish_dev_v1/`. On its domain-grouped validation set it reached PR-AUC **0.924** and ROC-AUC **0.918**. At the threshold selected for maximum recall under an empirical 1% validation false-positive-rate constraint, it had **97 false positives per 10,000** validation negatives and **43.8% recall**. The bundle is experimental and was not connected to runtime scoring.

The frozen candidate then scored the previously inspected PhishVN development corpus. On 3,089 rows its PR-AUC was **0.762**, recall **93.6%**, and false-positive rate **4,612 per 10,000** at the frozen threshold. This is poor transfer evidence and is not used to retune the model. The evaluator and report are under `lightgbm_dataset/fresh/external_evaluations/phreshphish_dev_v1_on_phishvn_development/`.

A new OpenPhish + PhishTank + Tranco snapshot dated 2026-10-17 was registered before scoring this candidate. It contains **52,485 URLs across 21,323 registrable domains** (42,485 source-reported phishing URLs and 10,000 Tranco controls). The candidate's training and validation domains have **zero overlap** with this snapshot. At the frozen threshold it flagged **275 of 10,000** Tranco proxy controls and detected **40.2%** of source-reported positives. The overall PR-AUC of 0.937 is driven in part by the 81% positive snapshot prevalence and is not a deployment estimate. Only **406 URLs from 292 domains** are novel against every prior project URL split; 405 are feed-positive and only one is a Tranco control, making that slice unusable for estimating a false-positive rate. The full snapshot remains a development benchmark because its positive labels are feed-reported, benign labels are Tranco/feed-absence proxies, most domains overlap previous project datasets, and campaign identifiers are unavailable. It is registered at `lightgbm_dataset/fresh/external_holdouts/20261017T153611845824Z/`; results are under `lightgbm_dataset/fresh/external_evaluations/phreshphish_dev_v1_on_20261017_snapshot_dev/`.

The evidence confirms that scale alone has not solved evaluation quality or transfer. Keep this candidate unpromoted. Next, acquire or independently adjudicate current benign controls and phishing samples, collect documented campaign/domain evidence, and register enough novel domains to create a temporally later two-class holdout. The current novel-domain subset has only one benign domain, so it must not be presented as a successful holdout evaluation. The LightGBM dataset test suite passed **56/56**; new scripts passed Ruff and Python byte-compilation, and dataset/model/evaluation bundles have checksums. Tests used the compatible local PyArrow runtime while the incompatible vendored PyArrow folder was temporarily moved and then restored.

## 2026-10-17 update: one-time PhreshPhish temporal test score

After the candidate bundle and threshold were frozen, the preregistered PhreshPhish test split was scored once using URL/label/metadata columns only; HTML was not downloaded. The test contains **167,966 valid unique URLs across 65,279 domains**, dated 2025-09-08 through 2025-12-16. Candidate train, validation, and test have zero URL, registrable-domain, or exact-page-hash overlap. At the frozen validation threshold, the candidate reached PR-AUC **0.924** (domain-bootstrap 95% CI **0.904–0.943**), ROC-AUC **0.929** (95% CI **0.918–0.939**), recall **44.2%**, and **97 false positives per 10,000** test negatives. This is useful same-corpus temporal evidence, but it does not establish cross-source performance; the model still produced **4,612 false positives per 10,000** on previously inspected PhishVN controls and 275 per 10,000 on Tranco proxy controls in the 2026 snapshot.

This test is **not a project-wide untouched holdout**: all 167,966 valid test URLs have domains in the pre-registration project inventory, and 149 test domains contain both labels. Domain conflicts were retained because labels apply to individual URLs; uncertainty estimates resample by registrable domain. Campaign identifiers remain unavailable. The authoritative evaluation is `lightgbm_dataset/fresh/external_evaluations/phreshphish_dev_v1_on_preregistered_test_dev_v2/`. It reconstructs the exact pre-registration inventory from 55 checksum-verified files; the earlier v1 report is superseded for inventory provenance. No test metric was used to change the model, threshold, or training set. **The candidate remains unpromoted** because this is the same corpus used for training, the project has previously inspected all these domains, and external false-positive performance remains unacceptable.

## 2026-10-18 update: MobileCLIP v3 external development comparison

The frozen `mobileclip_v3_dev_v1` head was scored once on the existing 1,310-image external manifest using its validation-selected threshold. The manifest was already used for v1/v2 development comparisons, so this is **not** an untouched release evaluation. Before scoring, the script verified the v3 bundle checksums and found zero known-domain overlap and zero exact-image overlap between the v3 fitting manifest and the external manifest. The 2,735 unknown-domain training images and unverified campaign relationships still limit overlap assurance.

Against MobileCLIP v2 on the identical images, sampling-weighted v3 PR-AUC/ROC-AUC were **0.115/0.739**, versus **0.114/0.731** for v2. V3 recall fell from **25.6% to 23.1%**, while its false-positive rate fell from **703 to 567 per 10,000 benign images**. The paired 1,000-replicate domain-bootstrap interval for the v3-minus-v2 FPR difference was **−224 to −63 per 10,000**; the recall difference interval was **−4.7 to −0.9 percentage points**. Both models miss the approved operational targets of at least 80% recall and at most 100 false positives per 10,000, so v3 is not a deployable replacement. The reproducible scorer and checksummed predictions/metrics are in `mobileclip-dataset/evaluate_mobileclip_v3_external_dev.py` and `mobileclip-dataset/artifacts/mobileclip_v3_external_comparison_dev_v1/`.
